# Zig conventions

## API Discovery

- Do not guess Zig APIs from memory or from examples targeting other Zig versions.
- Before using or changing a Zig API, run `zig env` and `zig version` to confirm the local toolchain and source layout.
- Use the paths reported by `zig env` as the source of truth, especially `std_dir` for the standard library and `lib_dir` for other bundled Zig libraries.
- Prefer evidence from local sources: symbol definitions, nearby tests, and existing call sites in this repository.
- If the needed behavior is not clear from `std_dir`, inspect other Zig sources and tests under the local `lib_dir` tree as needed.
- The local stdlib shows what an API is, not whether it is being retired: deprecated declarations still compile. Cross-check the release notes at `https://ziglang.org/download/<version>/release-notes.html` (for example `0.17.0`) for deprecation and removal lists before picking between alternatives.

## Runtime and Tests (Zig 0.17)

- CLI startup borrows `std.process.Init` resources and returns an exit code so standard-library cleanup runs. Do not create a second global I/O runtime or read the libc environment directly.
- Route `src/` runtime allocations through `app_runtime.gpa()`, `app_runtime.fastAllocator()`, or `app_runtime.scratchAllocator()` (src/core/runtime.zig) rather than naming `std.heap.smp_allocator`/`page_allocator` directly — Debug and test builds get SafeAllocator leak coverage; release keeps the unchecked allocators. Only deliberately process-lifetime allocations (e.g. the `systemProxy` cache) may bypass this, with a comment.
- Clone the startup environment map before changing a child process's environment. Test code falls back to the test runner's per-test I/O and environment.
- Use `std.Io.Dir.path` rather than deprecated `std.fs.path`. C time bindings are generated by the build's `TranslateC` module.
- Use `zig build test -Dtest-filter=<substring>` for focused checks and `zig build test test-helpers` for the full suite. Repeated `-Dtest-filter` flags match multiple substrings.
- CLI-output tests must capture a subprocess rather than write to the unit test runner's stdout, which carries Zig's `--listen=-` protocol.
